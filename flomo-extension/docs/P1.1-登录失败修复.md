# P1.1 修复：登录报「请传入 timestamp」

> 日期：2026-09-08 · 触发：用户真机登录失败

## 一、根因

不是 flomo 接口变了，是**我们移植时漏了/写错了三处**。回查 flomo-cli `client.py` 源码（已验证可工作的实现）后确认：

| # | 我们的错误 | CLI 正确做法 | 后果 |
|---|---|---|---|
| 1 | 公共参数里**没有 timestamp** | `timestamp: str(int(time.time()))` —— 秒级、字符串、**参与签名** | 服务端直接拒绝 → **「请传入 timestamp」（你看到的报错）** |
| 2 | 签名串拼成 `k=v&k2=v2&` + SECRET（末尾多个 `&`） | `"&".join(parts) + SECRET`（**末尾无 `&`**） | 签名校验失败 |
| 3 | POST/PUT 用 `application/x-www-form-urlencoded` | **JSON body**（`application/json`） | 请求被拒 |

**附带修正**（不影响登录，但会导致后续功能异常）：
- `tz` 不属于公共参数 —— 只在 `/memo/updated/` 与创建笔记时作为业务参数传
- `include_deleted` 是 CLI 的**本地过滤开关**，不是服务端参数 → 改为本地过滤（P3 实现）

## 二、改了哪些文件

| 文件 | 改动 |
|---|---|
| `src/shared/api/endpoints.js` | `buildFixedParams()` 加入 `timestamp`（每次现取），移除 `tz` |
| `src/shared/core/sign.js` | 拼接改为 `parts.join('&') + SECRET` |
| `src/shared/core/constants.js` | `webp` 改为字符串 `'1'`（与 CLI 一致） |
| `src/shared/api/client.js` | POST/PUT 改 JSON body；登录补 `wechat_union_id`/`wechat_oa_open_id`；创建笔记补 `source`/`tz`；同步移除 `include_deleted`；注入 `now` 便于测试 |
| `tools/verify-api.mjs` | 同步修正（timestamp / 签名 / JSON body） |

## 三、如何防止再犯

已把三处写进测试，任何一处回退都会立刻失败：

- **基准向量**：用 Python 算出 `md5("api_key=...&webp=1" + SECRET)` = `cf258898173933e2858d4dece8e2667a`，JS 实现必须逐字节一致
- **结构断言**：固定参数必须含 `timestamp`、不含 `tz`；timestamp 必须随 `now` 变化
- **格式断言**：PUT/POST 的 `Content-Type` 必须是 `application/json`；DELETE 不能带 body
- **行为断言**：连续两次请求 timestamp 不同 → 签名也不同

测试：**60 纯函数 + 56 准真机 = 116 项全过**

## 四、你接下来做什么

1. 在 `chrome://extensions` 点刷新重新加载扩展
2. 再次打开 Popup 登录 —— 应该能成功
3. 如果**还不行**，请把 Popup 里的完整错误文字发我（服务端原文会透传），不要再凭印象描述
4. 想一次性确认更多契约，可跑：
   ```bash
   node flomo-extension/tools/verify-api.mjs --email 你的邮箱 --password '你的密码'
   ```
