## R1 技术栈与验证（已确认）
| 项 | 决策 |
|---|---|
| 语言与构建 | **原生 JS + ES modules**（SW 声明 `"type":"module"`，零构建，改完重载即生效） |
| UI 渲染 | **原生 DOM + CSS**，零依赖 |
| 测试 | **Node 内置 `node:test`**（`node --test`，零依赖） |
| 验证深度 | **单测 + mock 联调** |
| mock 夹具 | **我造仿真样本**（10–20 条，含图片/音频/软删/层级标签；覆盖同秒 `updated_at`、空列表到底等边界） |
| 联调范围 | **地基链路：登录 → 同步 → 搜索**（后续每阶段按需追加） |

### R1 附加：UI 交互与视觉原则（用户指定，写进实现规范）
- **格式塔原理**组织界面元素（ proximity 相近分组 / similarity 同构同义 / closure 留白成组 / continuity 视觉动线连贯）
- **Affordance**：按钮/可点元素必须有可点击的外观暗示（游标、hover/active 态、阴影层级、禁用态可见）
- **Consistency**：同类控件视觉与行为一致（主次按钮、输入框、图标语义、间距节奏、文案语气统一）
- **识别优于回忆**（recognition over recall）：关键选项/状态可见可辨，不依赖用户记忆路径
- **渐进披露**（progressive disclosure）：高频操作前置，高级/低频项收进二级（设置、展开区）
- **美观 + 情感化设计**：动效克制有反馈（保存成功微动效）、空状态与出错态有温度（插画/拟人文案）、动效可降级（`prefers-reduced-motion`）

## R2 认证与登录（已确认）
| 项 | 决策 |
|---|---|
| 登录失败展示 | **透传服务端 message + 疑难指引**（不自建文案映射）；附排查引导如「去网页端确认能否登录」 |

> 影响：设计文档 §5.2 的 Token 优先级链改为「仅 `chrome.storage.local.access_token` → 提示登录」，**去掉「注入 token」优先级分支**（保留内部读取逻辑即可，不提供 UI 入口）。

## R3 划词录入（已确认）
| 项 | 决策 |
|---|---|
| 触发方式 | **用户可在设置页自定义**（本轮不定死默认值，交由设置项决定） |
| 触发选项集 | ① 选中→浮出小图标→点开小框 ② 选中直接弹完整小框 ③ 仅右键菜单 ④ **关闭划词浮层**（可在设置里彻底关掉） |
| 小框字段 | **内容编辑区 / 来源开关 / 标签输入行 / 保存后提示条** 四者全要 |
| 字段可自定义 | **内容区常驻不可关**（核心）；**标签行 + 来源开关可在设置里关掉**，默认全开 |
| 保存成功反馈 | **轻量 toast 后关闭**（不做原地成功态、不做撤销、不用系统通知） |
| 长文本 | **全存 + 小框可滚动**，不截断、不折叠、不做二次确认 |

> 落地约束：
> - 设置页新增 `capture_trigger`（四选一）与 `capture_fields`（`tags` / `source` 两个可关项，内容区恒定可见）。
> - content script **打开小框时重拉配置**（已有约定），否则设置改动在已开页面不生效。
> - 「关闭划词」时 content script 仍注入但只监听不渲染浮层（或按需注册），避免继续消耗 DOM 监听。
> - toast 由 content script 就地渲染，自动消失；`prefers-reduced-motion` 下不做位移只做淡入淡出。

## R4 同步与缓存（已确认）
| 项 | 决策 |
|---|---|
| 首次全量 | **后台静默分页 + 进度可见**：启动即拉，UI 顶部显示「同步中 3/5」，不阻塞操作；不做遮罩、不做懒加载 |
| 定时增量 | **可设置，默认 5 分钟**（设置页 1/5/15/30 分钟切换），走 `chrome.alarms` |
| 离线写 | **存进缓存标「待同步」，手动点才发**（不做联网自动重发） |
| 冲突 | **MVP 接受 last-write-wins，不提醒**（无版本/ETag，不做编辑前 `updated_at` 比对） |
| 队列可见性 | **只在设置页显示**（Side Panel 顶部不挂黄条、不做图标角标） |
| 队列失败项 | **标记失败 + 保留手工重试/删除**，不自动丢弃、不无限重试 |
| 待发笔记呈现 | **列表可见 + 半透明 / 「待同步」标记**（让用户知道已记下但未上传） |

> 落地约束：
> - 队列存 IndexedDB `outbox` 表：`{id, op:create|update|delete, payload, status:pending|failed, error, created_at}`。
> - 手动发送入口在设置页；发送时逐条走把关中枢，成功 upsert 缓存并出队，失败标 `failed` 并保留 `error`（稳定错误码）。
> - 列表渲染时按 `status` 加半透明样式与「待同步」徽标；`prefers-reduced-motion` 下不做闪烁动效。
> - 注意一致性：队列管理 UI 在设置页，但待发内容本身在主列表可见——两者不冲突，别做成两处都看不到。

## R6 设置页与 i18n（已确认，含矛盾校口结果）
| 项 | 决策 |
|---|---|
| 分组 | **账号 / 录入 / 同步 / 浏览 / 外观** 五组 |
| 清空缓存确认 | **点一次即执行，无需确认词、无二次弹窗**（校口后最终口径） |
| 清空范围 | **仅笔记/标签等缓存数据 + 游标**；保留 token、语言、设置项，清完不重登 |
| 同步时间显示 | **相对时间 + 悬停显示绝对时间** |
| 语言默认 | **默认中文，可在设置页覆盖**（不探测浏览器语言） |
| i18n 兜底 | **回落中文 + 单测拦截**（比对中英字典键集合/占位符/非空，缺键即失败） |
| 配置生效 | **底部「保存」按钮统一提交**（含语言在内全部都要点保存才生效） |
| 未保存离开 | **自动保存**（离开即落盘，不静默丢弃，不弹拦截） |
| 恢复默认 | **不做**（不提供单组/全局重置入口） |

> 校口说明：本轮出现两处前后不一致（清空确认、保存方式），已按第二轮校口回答定稿，上表为最终口径。
> 「统一提交 + 离开自动保存」的组合含义：改动先入暂存态，点「保存」立即广播生效；未点保存就离开时视为保存，不丢弃。
> 落地约束：保存后走总线 `config_set` → 后台广播 `flomo:config-changed`；content script 打开小框时重拉配置（避免陈旧）。清空缓存按钮需写清「不影响 flomo 云端」以降低焦虑（情感化）。

## R5 浏览 / 搜索 / 回顾 / 推荐（已确认）
| 项 | 决策 |
|---|---|
| 列表渲染 | **分页 / 滚动加载，每页 50**（不做虚拟列表、不全量渲染） |
| 搜索 | **本地全量 + 高亮命中**（缓存内即时过滤，防抖 200ms，高亮匹配片段） |
| 每日回顾 | **内容由官方 API `/memo/notify_of_today/` 决定**（扩展不自己挑）；呈现 = **Side Panel 顶部可折叠区块，进入即加载**，不主动弹通知 |
| 相关推荐 | **由官方 API `/memo/{slug}/recommended?type=1` 决定**；呈现 = **详情页底部展示**（按需加载，不在列表页逐条内联） |
| 相似度呈现 | **按相似度降序 + 轻量条形/百分比**（不显示原始两位小数） |
| 回顾/推荐缓存 | **不缓存，实时拉取**（与笔记列表缓存策略相反，明确区分） |
| 离线时这两块 | **显示「离线不可用」占位**，不静默隐藏、不假装有数据 |
| 列表排序 | **用户可自定义**：更新时间/创建时间 × 倒序/升序 共 4 种，**默认「更新时间倒序」** |
| 标签筛选 | **顶部标签云，点击切换**（首版只筛不改，符合 R6 不做标签管理） |
| 搜索结果排序 | **复用列表当前排序**（搜索=过滤，不另起打分逻辑） |

> 落地约束：
> - 排序与筛选状态存 `chrome.storage.local`（`list_sort` / `list_tag`），重启保持。
> - 「不缓存」只针对回顾与推荐；**笔记列表与搜索仍走 IndexedDB 缓存**（R4 已定），别混淆两条策略。
> - 回顾/推荐请求失败时按错误码分流：`not_authenticated` → 走登录中枢；网络/离线 → 占位文案；其余 → 区块内错误提示。
> - 标签云数据来自缓存 `tags` 表（由同步 upsert 维护），不是单独请求 `/tag/tree`。

## R7 Agent 接口（已确认：降级取消）
| 项 | 决策 |
|---|---|
| 对外暴露 | **取消**：不设 `externally_connectable`，外部网页 / 其他扩展**不能**调用（因此无需鉴权、分级、白名单） |
| 内部通道 | **保留**：UI（popup/sidepanel/options/content）↔ SW 的 `chrome.runtime.sendMessage` 照常建设（CORS 必需，属内部实现） |
| envelope | 内部消息仍用 `{ok, data, has_more/total, error}` 形状保持代码一致，但**不作为对外契约与承诺** |

> 影响：设计文档 §5.5「Agent 接口」与阶段计划 **P7（Agent 接口文档+示例）整体取消**，不留待办。
> 概念区分（记档）：**内部调用** = 扩展自家页面/脚本 ↔ 自家后台；**外部调用** = 别的网页、别的扩展通过浏览器对外通道调本扩展。本扩展只开前者。

## R8 权限与隐私（已确认）
| 项 | 决策 |
|---|---|
| 数据边界 | **只存本机，零上报**：chrome.storage + IndexedDB；不接统计/崩溃上报，代码内无第三方域名请求 |
| manifest 权限 | **最小权限**：`storage / contextMenus / sidePanel / commands / alarms / notifications` + host 仅 `https://flomoapp.com/*`；**不要** `tabs`、不要 `<all_urls>` |
| content script | **所有页面注入**（划词需在任意网页生效）；空闲注入 + 轻量监听，页面加载时不干重活 |
| 权限缺失日志 | **console 结构化日志 + 设置页开关**：统一 logger，默认 `warn/error`，可开 debug；权限缺失明确打点 |
| 日志脱敏 | **不记录 token / 密码 / 笔记正文**，仅记端点、错误码、耗时、条数 |

### 目录结构（最终）
```
flomo-extension/
├── manifest.json            # 根目录只放 manifest / README / package.json
├── src/
│   ├── shared/
│   │   ├── core/            # 纯函数，零平台依赖，最好测：sign / format / errors / memo / http-status
│   │   ├── api/             # 传输层：client（签名+端点+响应处理）/ endpoints / retry
│   │   └── platform/        # 平台适配，可 mock：storage(chrome.storage) / idb / logger / alarms / i18n
│   ├── background/          # service-worker 入口 / message-bus 把关中枢 / sync 调度
│   ├── content/             # selection 划词浮层 / floating-ball / toast
│   └── ui/                  # 薄 UI：popup / sidepanel / options / login / shared 样式与组件
├── assets/
└── tests/{unit,integration,fixtures}/
```
> 三条硬规矩：① `core/` 不许 `import chrome.*`；② `platform/` 是唯一允许碰 `chrome.*` 与 IndexedDB 的地方（UI/background 通过它间接使用）；③ UI 层不写业务逻辑，只发消息 + 渲染状态。

## R11 功能边界（已确认）
| 项 | 决策 |
|---|---|
| 编辑 / 删除 | **都不支持，扩展只写入不修改**（误记内容去 flomo 官方客户端处理） |
| Popup 速记框 | **多行输入 + `Ctrl/Cmd+Enter` 保存**；底部入口跳 Side Panel / 设置 |
| 图片 / 音频 | **只显示「含图片/音频」标记**（不渲染缩略图、不做附件上传） |
| 未登录首次打开 | **点图标直接进登录页**（不展示空列表、不做功能介绍页） |

> 影响：`PUT /memo/{slug}`（更新）与 `DELETE /memo/{slug}` 在扩展中不实现，API 契约仅留档不调用。
> 待确认（R13 审计项）：R3 选的「toast 后关闭」与此处「不删除」一致——即**不提供任何撤销能力**。

## R12 边界处理（已确认）
| 项 | 决策 |
|---|---|
| 空内容 / 超长 | **前端校验空内容**（禁用保存按钮）；**超长不设前端上限**，交由服务端判定并按错误码提示 |
| 文本转换 | **照搬 CLI `_text_to_html`**：每行包 `<p>`，`#标签` 原样保留（换行与标签行为与 CLI 对齐） |
| 慢网 / 超时 | **设超时阈值（建议 10s）→ `timeout` 错误码 + 可感知加载态**，不无限转圈 |
| 首次同步中断 | **整批一个事务，中断即重来**（不做断点续传；已落页不保留，下次从头拉） |

> 落地约束：整批事务意味着首次同步期间 SW 被杀死则已拉数据全部回滚；需在中途失败时给出明确提示，避免用户以为已同步。

## R13 冲突审计（已确认，含 2 处推翻）
| # | 审计点 | 结论 |
|---|---|---|
| ① | 离线待发易被遗忘 | **推翻 R4「手动点才发」：改为联网自动发送，不询问**（低频场景优先省心） |
| ② | 首次同步中断后用户不知情 | **同步状态持久化**：写入 storage，重启显示「上次同步未完成，点此重试」 |
| ③ | 「不编辑不删除」导致误存无法处理 | **推翻 R11「不删除」：破例开放删除**，但**仅限本扩展本次会话刚创建的笔记** |
| ④ | 全站注入浮层可能干扰特殊站点 | **设置页提供站点黑名单**（支持域名/通配，预置常见冲突站点），黑名单内不渲染浮层 |
| ⑤ | 删除范围 | **仅删除本扩展本次会话刚创建的笔记**；**点一次即删 + toast 给撤销**（不做二次确认弹窗） |
| ⑥ | 离线方案定稿 | 队列保留、设置页可见、**联网自动发送**，不主动打扰、不做定时提醒通知 |

> ⚠️ 遗留矛盾（移交 R14）：flomo 的 `DELETE /memo/{slug}` 是**软删**，删除进回收站，**扩展无法通过再调一次接口撤销**。因此「toast 给撤销」若指"把笔记恢复回来"在技术上不成立，需重新定义撤销语义。
> ⚠️ 影响：R4 表内「离线写：手动点才发」一行作废，以本表①⑥为准；R11 表内「编辑/删除：都不支持」一行作废，以本表③⑤为准。

## R14 冲突审计（已确认，含 1 处推翻）
| # | 审计点 | 结论 |
|---|---|---|
| ① | 软删不可恢复，「撤销」语义落空 | **语义定为「真删 + 提示去回收站找」**：点撤销即调 `DELETE`，toast 明说「已删除，可在 flomo 回收站恢复」 |
| ② | 英文界面下服务端中文报错 | **直接透传不翻译**：主要场景是中文界面，返回中文就显示中文；附错误码便于查证（不做本地化映射） |
| ③ | 浮层被宿主页面 CSS 污染 | **Shadow DOM 全隔离**：划词浮层 / toast 全挂进 Shadow Root，自带样式变量 |
| ④ | 三个录入入口是否都要 | **推翻 R9 悬浮球：只留「划词浮层 + Popup 快捷键」，悬浮球整个砍掉** |

## R18 架构逻辑审计决议（2026-09-08，开工前必须遵守）
详细审计见 `/data/workspace/flomo-extension-架构审计报告.md`。以下为**覆盖前面所有轮次**的最终口径。

### 用户拍板 5 项
| 项 | 结论 |
|---|---|
| 注入范围 vs 权限 | **接受全站警告**：`content_scripts.matches=<all_urls>`；`host_permissions` 仍**仅** flomoapp.com；站点黑名单保留 |
| 详情渲染 | **全部纯文本化**（html_to_text 剥标签），只留「含图片/音频」标记 → **推翻 R5-4「渲染原始 HTML」**，无 XSS 风险 |
| 排序/筛选 | **浏览态**：列表顶部控件**即时生效并存 storage**，不走设置页保存按钮；设置页只放「默认排序」 |
| 撤销窗口 | **取消落盘**，撤销跟 toast 同寿（约 6 秒）→ **推翻 R15-1 的 5 分钟落盘** |
| 划词默认触发 | **改回「浮出小图标」**（推翻 R15 定稿的「选中直弹」），直弹保留为可选项 |

### 技术别无选择，直接定 3 项
| 项 | 结论 |
|---|---|
| 首次同步事务 | **推翻 R12-4**：IDB 事务无法跨网络 await，整批事务物理不可实现 → **每页独立事务 + 游标即时落盘**，中断续跑 |
| 同步进度显示 | 取消「3/5」假分母，改「已同步 N 条…」 |
| 队列发送 | SW 无 online 事件 → **三路兜底 flush**：alarms 同步前 / 打开 UI 时 / 保存成功后 |

### 风险偏向一边，直接定 2 项
| 项 | 结论 |
|---|---|
| 清空缓存范围 | **outbox 不清**（否则永久丢失云端没有的内容），按钮写明「不影响未发送的笔记」 |
| i18n 排期 | **i18n 字典骨架 + 设计 token 前置到 P0**，避免 P4/P5 返工 |

### 硬依赖（P1 必须验证）
`PUT /memo` 响应**是否含 slug** → 决定 R13「破例删除 + 撤销」能否成立。不含则走 `/memo/latest_updated_desc` 退路；再不行则砍掉撤销回到 R3。

### 依赖方向（写死）
`core` ← `api` ← `background`；`platform` 可被任意层依赖；**禁止 UI 直接 import `api`**，禁止反向依赖。
配置传播统一用 `chrome.storage.onChanged`（SW 无法主动推消息给 content script，除非要 tabs 权限）。

## R19 补充维度扫描决议（2026-09-08）
详见 `/data/workspace/flomo-extension-补充维度扫描.md`。此前从未讨论过、现已定稿的方向：

| 项 | 结论 |
|---|---|
| **图标行为（F）** | 点击工具栏图标**智能分流**：未登录 → 弹 Popup 登录页；已登录 → 开 Side Panel（速记框置于侧边栏顶部）。Popup 与 Side Panel 默认行为二选一，靠状态分流兼得 |
| **接口失效（A）** | 要**专门提示 + 防御式解析**：未知错误码/响应结构异常 → 提示「flomo 接口可能已更新」；字段缺失给默认值不炸链；集中 `API_COMPAT_VERSION` |
| **客户端身份（B）** | `device-id` = 首次生成 UUID **持久化复用**（禁止每次随机）；UA 伪装普通 Chrome 不带扩展标识；遇 -20 引导去网页端验证；token 不设本地过期，以服务端 -10 为准 |
| **限流（C）** | 请求串行队列 + 最小间隔 300ms；429/5xx → `rate_limited` 退避 5 分钟并暂停定时同步 |
| **同步锁（D）** | `sync_lock` 存 storage 带时间戳，超 5 分钟自动释放防死锁；三触发源抢锁 |
| **内容转义（E）**★ | 写入前先 HTML 转义（`<`→`&lt;` 等）再包 `<p>`，否则纯文本化显示会**吞掉用户写的尖括号内容**。这是"全部纯文本化"能成立的必要前提 |
| **浮层关闭（G）** | Esc + 点外部 + 关闭按钮三重；保存成功自动关闭；浮层内 Tab 循环不跑到宿主页 |
| **无障碍（H）** | aria-label、:focus-visible、键盘可达、reduced-motion 降级——补进 UI 原则 |
| **时区（I）** | 日期解析统一按 **UTC+8**（对齐服务端 `tz=8:0`），不依赖本地时区 |
| **用户信息（J）** | 登录后调 `/user/me` 存 nickname/email 供设置页显示，登出清除 |
| **IDB schema（K）** | `DB_VERSION=1`；stores：`memos`(slug) / `tags`(name) / `outbox`(id autoInc) / `meta`(key，存游标)；预留升级分支 |
| **测试盲区（L）** | `platform/idb` 可替换 backend（测试注入内存实现）；DOM 相关逻辑抽纯函数（rect→坐标）脱离 DOM 可测 |
| **iframe（M）** | 首版 `all_frames:false` 避免重复注入；iframe 场景靠右键菜单兜底 |
| **初始化（N）** | `onInstalled`/`onStartup`：初始化默认配置 → 注册 alarms → 注册右键菜单 → 已登录则增量同步一次 |
| **自检面板（O）** | P0 建 logger + 脱敏（各模块直接调用），**面板 UI 放 P6** |
| **缓存导出** | 不做，缓存可从云端重建 |
